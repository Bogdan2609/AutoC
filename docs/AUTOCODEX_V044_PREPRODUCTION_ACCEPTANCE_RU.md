# AutoC v0.44.0 — Preproduction Acceptance

Дата: 26.10.2026. Основание: утверждённый `AUTOCODEX_MASTER_ROADMAP_V040_V044_2026-10-26.md`, пункты G44-01…G44-06.

## Решение о реальных операциях

**`live_money_decision = NO_GO`.** Установка этого пакета, прохождение unit-тестов, наличие evidence и здоровый `/readyz` **не** разрешают СБП, возвраты, фискальные чеки или закупки поставщикам. Никакой скрипт в v0.44 не меняет флаги разрешения live-операций. Любой внешний непроверенный WRITE строго запрещён.

Пакет — воспроизводимый **инструментарий предпродакшен-приёмки**, а не заявление о завершённой приёмке. Внешние sandbox-испытания и договорные условия не могут быть подтверждены локальной сборкой; до предоставления доказательств они BLOCKED.

## Что делает пакет

- Версия 0.44.0, исправленная явная RBAC-классификация административных API v0.43 и v0.44; подключённый read-only административный API `GET /api/v1/backoffice/preproduction-v044/gates` под `require_admin`, интерфейс `/admin/system/preproduction`.
- Локальный синтаксический/архитектурный `scripts/release_gate_v044.py` без доступа к БД и сети.
- `scripts/acceptance_report_v044.py` составляет **только** отчёт о наличии доказательств и их SHA-256. Даже при всех документах статус остаётся NO_GO и human validation pending.
- Unit/HTTP тесты и дополнительный `test_postgres_preproduction_v044.py` для изолированной PostgreSQL 18.6. Тест не выполняет `drop_all/create_all`; создаёт при необходимости только `jobs` в явно указанной disposable-БД и удаляет только собственную тестовую запись.
- Инвентаризация 15 критериев с четырьмя группами: техническая, внешняя, юридическая, управленческая.

## Обязательная изоляция испытаний

- `TEST_DATABASE_URL` и `AUTOCODEX_TEST_PG_URL`: **только временная** PostgreSQL 18 на `127.0.0.1`, для v0.44 имя БД должно быть `autoc_test_v044`.
- Не направлять команды `pytest` с `TEST_DATABASE_URL` на production: существующие pytest fixtures могут создавать/удалять таблицы.
- Для общей SQLite-регрессии задавать `-e TEST_DATABASE_URL=` и `-e AUTOCODEX_TEST_PG_URL=` явно. Для PostgreSQL-тестов лучше использовать отдельный `docker run --network container:autocodex-pgtest-v044` с минимальными permissions и принудительно выключенными live flags.
- Не выполнять `alembic downgrade` на пользовательской базе. Миграционную приёмку производить только на обезличенном `pg_restore` в disposable volume.
- Подтверждение установки v0.43 **не предоставлено**: перед установкой v0.44 требуется успешный preflight v0.43 и прохождение регрессии v0.43 в Docker.

## Где фиксировать результат

1. Создать локальную папку `evidence_v044` и положить в неё только очищенные от секретов артефакты.
2. `manifest.json` — JSON словарь `"G44-01A": ["docker-build.txt"]` и т.д. Имена — относительные имена файлов внутри `evidence_v044`.
3. Вызвать `python scripts/acceptance_report_v044.py --output evidence_v044/report.json --evidence-dir evidence_v044 --manifest evidence_v044/manifest.json` (если доказательств ещё нет, только `--output`).
4. Скрипт фиксирует SHA-256 каждого файла и дату отчёта. Он **не проверяет правдивость внешнего документа** и не изменяет состояние приложения.
5. Предпродакшен-акт подписывается вне AutoC. Даже после подписания включение real-money остаётся отдельной процедурой с отдельной авторизацией, конфигурацией и мониторингом.

## Текущие открытые блокеры

- В текущем диалоге нет лога установки/полного тестирования v0.43.
- Не продемонстрированы YooKassa SBP sandbox e2e, банки/возвраты и фискализация.
- Не подтверждены courier-only create/cancel/idempotency и минимальная сумма заказов для всех четырёх поставщиков в их действующих кабинетах.
- Юридический статус продавца, фискальные обязанности и договора не подтверждены.
- Для v0.43 существует открытое ограничение: fencing финального статуса **не покрывает все промежуточные коммиты старых worker handlers**.
- SQL/load/DR/staging миграции из реального обезличенного состояния и rollback не продемонстрированы.

**Поэтому релиз v0.44.0 = acceptance tooling candidate; GO/NO-GO для финансового контура остаётся NO_GO.**
