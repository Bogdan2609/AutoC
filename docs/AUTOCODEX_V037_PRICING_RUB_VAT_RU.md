# Autocodex v0.37.0 — финансы, цена RUB и контроль валовой маржи

**Основа: v0.36.0.** Инкрементальное обновление поверх указанной версии. Только RUB; мультивалютность — отдельный будущий эпик. Никакой конвертации, арифметика денег выполняется Decimal.

## Реализовано

1. **Последняя миля в правилах файловых предложений.** У `FeedPriceRule` теперь есть явно конфигурируемый `last_mile_delivery` (Numeric(14,2)); администрация может задавать это значение в `/api/v1/admin/supplier-feeds/pricing/policies`. В утверждённой цене оно участвует в себестоимости и покрытии комиссии СБП. Старые вспомогательные in-memory правила без поля работают с нулём, но не должны быть автоматически утверждены.
2. **Повторное согласование.** Миграция `20261026_0037` добавляет поле и сбрасывает `approved` всем ранее одобренным правилам `feed_price_rules`. Необходим пересмотр фактической стоимости доставки и повторная ручная процедура approve. Это **намеренное изменение данных**, откат схемы не возвращает прежние approval-флаги.
3. **НДС.** Предварительная калькуляция по файловому предложению больше не считает `tax_status=excluded` валовой закупочной ценой. Текущая модель исходит из документированного `RUB`, `purchase`, `tax_status=included`; для фидов без НДС в цене потребуется подтверждённая методология определения итоговой закупочной стоимости и отдельная реализация. НДС в F1/F2 — только **модель за 2026 год**, без обещания соответствия фактической налоговой базе, вычетам и кассовым чекам.
4. **MARKUP_SIMULATION.** База наценки теперь учитывает все задокументированные денежные затраты: закупку, закупочную доставку, доставку клиенту, упаковку, прочие затраты и налоговый резерв. Это **меняет цифру симуляции**, не цены реальных заказов.
5. **Fail-closed preview.** Когда денежный вклад после списания расходов и комиссии СБП меньше минимального, preview отмечается `SIMULATION_CONSTRAINT_FAILED`. Если указан режим НДС и расчётная маржа после НДС меньше запрошенного минимума, также возвращается отказ по ограничениям. При неизвестном налоговом режиме нет заявления о чистой прибыли: `minimum_contribution_met = null`, дополнительно возвращается `cash_minimum_contribution_met`.
6. **Коммерческий ценовой предел.** Необязательное поле `PricePreview.max_price_delta_pct` (0–500) ограничивает цену относительно подтверждённой валовой себестоимости в симуляции. Превышение приводит к `SIMULATION_CONSTRAINT_FAILED` без скрытого изменения цены; `max_price_delta_met` возвращается явно. Для реальных продаж потребуется согласование конкретного значения по коммерческому правилу.
7. **SBP-лимит на shadow-политики.** Для новых API-правил `FeeInput(fee_kind='SBP')` и `PricePolicyInput` процентная комиссия ограничена 10% как **предохранительный потолок, а не утверждение об актуальном тарифе банка**. Исторические правила с большими значениями нельзя одобрять без переработки политики. Ставки и caps должны определяться договором и проверяться отдельно. Иной `MARKETPLACE`-тариф не получил этого ограничения.
8. **Строгие деньги.** Финансовое ядро отклоняет float, неверные значения комиссии и кэп, имеющий дробные копейки. Выходные денежные суммы остаются округлёнными до 0.01 RUB.
9. Версия backend `0.37.0`, предыдущий внешний контракт `PROVIDERS` не меняется. Реальная публикация офферов, checkout, закупки и возвраты **не активируются** этой версией.

## Ограничения и следующая работа

- `Finance F2` **остаётся административной симуляцией**. Эндпоинт `overview` сообщает `live_pricing_integration_enabled=false`. Нельзя выдавать эту версию за готовый боевой pricing/settlement.
- Изменение налоговых режимов, зачёта входного НДС, чеков YooKassa, банковских комиссий и фактической доходности подлежит отдельному юридическому, бухгалтерскому и операционному подтверждению.
- Требуется Docker-проверка миграций на PostgreSQL 18.6, **резервная копия БД до миграции** и ручной повторный approve после проверки себестоимости.
- После изменения значений цены в симуляции сравнить модель с договорными закупочными ценами, доставкой, упаковкой, комиссиями СБП, фискальными документами и реальной маржой.
- Для VAT-exclusive предложений нельзя вручную проставлять `included`, чтобы обойти блокировку. Добавить правильную методологию отдельным этапом.

## Проверки на Windows / PowerShell (каждая команда — одна строка)

После установки ZIP и **сохранения резервной копии БД**:

`Set-Location 'C:\Users\bogdan\Desktop\autocodex'; docker compose up -d --build; docker compose ps`

`Set-Location 'C:\Users\bogdan\Desktop\autocodex'; docker compose logs --tail=120 migrate web worker`

`Set-Location 'C:\Users\bogdan\Desktop\autocodex'; docker compose exec web uv run --no-sync python -m pytest -q tests/test_pricing_safety_v037.py`

Тесты через `docker compose exec web` потребуют наличия `pytest` в контейнере; при `uv sync --no-dev` dev-зависимости могут отсутствовать. В таком случае тесты запускать в специально собранном dev-окружении или CI, не устанавливая dev-пакеты в боевой контейнер.
