# AutoC v0.40 — Transaction Safety (integrable candidate)

Дата: 26.10.2026. База: `bc6266025c63d4c7ac9247ce9e1708c8d1620d90` (`0.39.0`). Формат: исходно-проверяемый ZIP с установщиком. **Статус: candidate, NO-GO для реальных денег.** Не утверждать, что интеграционные и PostgreSQL-тесты прошли до запуска на целевом репозитории.

## Реализовано в пакете

- Pure ASGI `BoundedRequestMiddleware` без обращения к `request._body`. Потоковый лимит JSON для `POST/PUT/PATCH/DELETE`, webhook 16 KiB, дорогой публичный API 64 KiB. Multipart остаётся ответственностью ingress и отдельных endpoint-валидаторов.
- Одинаковая UTC-нормализация для клиентских и административных сессий; фильтрация logout по текущему пользователю.
- Неизвестные HTTP-методы отвергаются ролью RBAC вместо автоматического WRITE.
- Идемпотентный тестовый checkout блокирует User перед поиском заказа, использует существующий unique `(user_id,idempotency_key)`, возвращает 409 на `IntegrityError`. Ключ не может быть использован с другой полезной нагрузкой.
- Единый строгий Decimal-контракт для summation payable order lines при создании тестового checkout, webhook settlement и материализации исполнений. Нельзя округлять 0.005 до 0.01 внутри settlement.
- Redis webhook lease с криптографическим owner token, атомарными Lua compare-delete/renew, TTL 60s и heartbeat; другие владельцы не могут удалить новый lease. Вторая одновременная попытка получает retryable 503, а не ложное 200.
- Детерминированный выбор payment attempt (`succeeded` > unsettled > canceled), сортировка по `created_at,id`.
- Ручная финансовая очередь `payment_manual_review` для платежей без provider ID старше 2 минут. Увидеть её можно через существующие операционные очереди и `/api/v1/payments/admin/payments/needs-reconciliation`. Новые попытки списания не создаются.
- Оператор не может подтвердить поставку, пока Procurement ещё `pending`; ручное подтверждение теперь фиксирует explicit provenance и actor id (когда доступен).
- `GET /api/v1/admin/supplier-purchases/attention`: read-only список попыток закупок, требующих безопасной сверки; ни одна автоматически не повторяется.
- Новый документ о блокировках, регрессионные тесты, GitHub Actions workflow Python/PostgreSQL/TS и read-only `scripts/release_gate_v040.py`. Версия пакета Python `0.40.0`.

## Не включено / блокеры завершения v0.40

1. Полный allow-list всех admin WRITE маршрутов: широкие префиксы всё ещё допускают наследование scope новыми путями. Нужна схема аудита маршрутов, согласование прав по всем существующим ролям и регрессионные тесты.
2. Реальные PostgreSQL race-тесты с **одновременно активными независимыми соединениями** для всех графов блокировок. Текущая CI добавляет PostgreSQL job, но это ещё не доказательство закрытия всех гонок.
3. Безопасное автоматическое восстановление `validating`: без отдельного fencing нельзя просто сбрасывать в prepared. Сейчас предусмотрена read-only диагностика.
4. Полная маршрутизация account + edge budgets и trusted-proxy deployment tests; применение multipart streaming limits на ingress.
5. Lock-файлы `uv.lock` и `admin-ui/package-lock.json` не генерируются в офлайновом пакете; CI пока использует npm install, Dockerfile остаётся без изменений. Для детерминированной сборки сгенерировать lock на сетевом хосте, проверить, затем заменить `npm install` → `npm ci` и включить `uv --locked`.
6. Полноценная политика retry (только до внешнего WRITE) и большой набор сценариев корректности state-machine; требуется интеграция и ручная проверка существующих маршрутов UI.

**Техническое определение:** это *реально подготовленные изменения*, но не финальная приёмка релиза v0.40. Не активировать боевые SBP/закупочные flags после установки.

## Установка — Docker Desktop + PowerShell

Смотрите README_RU.md внутри ZIP. Корректирующая сборка `v040_fixed.zip` запускает Python **только в одноразовом Docker-контейнере**, предоставляет `--check` и `--apply`, затем требует повторной проверки и сборки через `docker compose`. Устаревшие указания запуска `python` непосредственно в PowerShell не использовать.

## Сохранённые запреты

СБП-only, courier-only, складские контакты в GetCheckout, UUID заказа в ROSSKO PARTS.Part.comment, запрет дублирования неопределённого внешнего WRITE, отсутствие оплаты provisional заявки, producer flags по умолчанию OFF. Ни миграций, ни запросов к внешним API в установщике нет.
