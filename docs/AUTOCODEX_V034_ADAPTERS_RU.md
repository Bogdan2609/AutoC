# Autocodex v0.34.0 — единые READ-адаптеры поставщиков

## Основа и способ установки

Инкрементальный ZIP поверх **v0.33.5** (предполагается последовательная установка v0.33.3 → v0.33.4 → v0.33.5). **Не является полным проектом.** Манифест V034_MANIFEST.json фиксирует SHA-256 заменяемых исходных файлов предыдущей версии и новых файлов. Не устанавливать поверх неизвестной ветки без проверки хешей.

## Изменения

1. Единственный боевой registry `app/modules/offer_engine/providers.py`: `PROVIDERS`, `get_adapter()`, `verify()`. Старый путь импорта `app.modules.suppliers.adapters.*` — ленивые алиасы к этому registry, без копии реализации и без циклического импорта.
2. Типизированный READ-интерфейс `SupplierAdapter(search, check_stock)`, единая реализация `ReadAdapter.check_stock()` (свежий поиск, точный SKU, ограничение по остатку, минимальная партия и кратность). Проверка остатков **не резервирует** цену/остаток, перед оплатой нужна повторная проверка в checkout.
3. Единая модель `Offer` вынесена в `app/modules/offer_engine/contracts.py`. Цена обязательно `Decimal` с точностью 0.01; `currency='RUB'`, количество >=0, кратность и минимум >=1; float и NaN запрещены.
4. Четыре чистых парсера в `app/modules/offer_engine/parsers.py`: JSON PARTKOM, JSON Forum-Auto, ADEO XML (через defusedxml), ROSSKO SOAP (результат Zeep). Маппинг отделён от transport (HTTP/SOAP). Битые структуры и пустая/иная валюта вызывают типизированную ошибку, не «пустые предложения».
5. JSON сохраняет десятичные числа через `parse_float=Decimal`, без float; ответ каждого поставщика ограничен проверкой размера после HTTP и количества строк (не заменяет лимиты тела ответа на reverse-proxy). Для ADEO XML запрещена обработка опасных сущностей.
6. Circuit breaker теперь **по (supplier_code, account_id:destination_id)**, а не общий для всех аккаунтов поставщика. `for_account` присваивает внутренний scope только на основе UUID account/destination; секреты не включаются. Восстановление half-open и освобождение probe после cancellation покрыты тестами.
7. Retry/backoff/jitter применяется **только к READ**; 5xx, 408, 429 и network timeout — retryable; 4xx, повреждённые ответы и неподтверждённая валюта — без повторов. Реальные order/checkout/cancel никогда не вызываются через этот retry-механизм.
8. Версия `pyproject.toml` и fallback `/openapi.json`: `0.34.0`.

## Что намеренно не включено

- **Никакой автоматической отправки заказов** у ADEO, PARTKOM, Forum. `SupplierPurchaseAdapter` — описание *необязательного* отдельного WRITE-контракта, а не реализация или разрешение. Реальный ROSSKO-контур `marketplace.procurement` оставлен без изменений.
- Никаких изменений правил: оплата только СБП; закупка только после подтверждённой оплаты; **исключительно курьерская доставка**, только разрешённый адрес и контакты своего склада/ПВЗ; UUID заказа в `ROSSKO PARTS.Part.comment`.
- Не добавлялись курсы, мультивалютность, автоматическое предположение RUB. При реальном ROSSKO GetSearch без явного поля валюты данные будут **отклонены**, пока валюта не подтверждена безопасным документированным источником. То же относится к другим API.
- `order_status` и `cancel_order` не объявлены функциями READ-адаптеров, потому что отсутствуют проверенные контракты + состояние реальной закупки для всех четырёх поставщиков. Они относятся к v0.35.
- Доработка атомарности коммерческих транзакций, финальных цен/НДС, reconcile возвратов и security-hardening — отдельные этапы v0.36–0.38.
- Новых миграций Alembic **нет**. Секреты и `.env` не включены.

## Тесты

- Новый файл `tests/test_supplier_adapter_v034.py` с синтетическими фикстурами `tests/fixtures/v034_*`: RUB/Decimal для 4 поставщиков; неопределённая валюта, некорректные JSON/XML, XXE, max-size; packaging/stock, alias/registry; circuit per-account, cancellation, WSDL cache без Zeep-сети.
- Должен использоваться `python>=3.14` по `pyproject.toml`, PostgreSQL/Docker для релизного integration gate; локальные выборочные прогоны в текущей среде (Python 3.13) проходят, но не подменяют Docker acceptance.
- Выборочный регрессионный прогон **174 passed** до последних двух тестов WSDL/credentials и смены номера версии. Автономно `tests/test_supplier_adapter_v034.py`: **39 passed**. Полный прогон в текущем окружении превышает доступный лимит времени и **не подтверждён**.

## Ручная приёмка до production

1. Docker build на Python 3.14, postgres+redis; все тесты `pytest` и интеграционные миграции.
2. Для каждого из 4 поставщиков: проверка реальной формы ответа в безопасном read-only режиме на отдельном аккаунте, с контролем `currency` без секретов в логах.
3. Проверка двух независимых аккаунтов одного поставщика с недоступностью одного: второй продолжает поиск. Проверить разные курьерские destination и отключение во время запроса.
4. Серия повторных READ (5xx, timeout, malformed 200, non-RUB, 401) и проверка, что сеть, кэш, breaker и audit корректно фиксируют каждый исход; нет повторных заказов.
5. Отдельно подтвердить документированный currency field у ROSSKO и других API; не исправлять этот случай «currency=RUB по умолчанию».
6. Изолированная проверка SOAP Zeep/WSDL на длительной работе + stop/restart воркера и закрытие соединений.
7. Только после этого v0.35: контракты write/status/cancel в песочницах, идемпотентный outbox и валидация курьерской доставки/реквизитов/контактов. Реальные chargeable заказы без отдельного разрешения не отправлять.
